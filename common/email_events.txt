Explanation of fields:
event = is the name of the event (corresponds to the tool) that will be looked for to auto-kick of the email.
    For example, when dns lookup finishes, the parser will automatically send emails to the appropriate people (based on
    who has been marked to receive emails and if the corresponding message is not blank).
tester_msg = is the message body that will go to whoever kicked off that tool to run
client_msg = is the message body that will go be send to all Client Contacts who are designated to receive notifcations
corp_msg = is the message body that will go to all of your company's staff you've identified to receive notifications
subject = is the email's subject (notice this is the same for all 3 groups of people that could receive an email for
    the event
* If a message is blank (ex. client_msg is blank, than that means no message will be sent to Client Contacts for that
    event even if they have it marked to receive notifications.  The same is true for the tester and your company
    (corp_msg) contacts.
* Wildcards:  There are certain reserved words in all CAPS that will automatically be substitued when the email is sent,
    that list is as follows:
        CLIENTNAME = the name of the Client (Company Name)
        ENGAGEMENT = the engagement # you entered for the current engagement
        SERVICE = the name of the service (SMTP, HTTP, etc)
        DOMAINNAME = the domain name (from a Scope entry)
        SCENARIONAME = the email phishing scenario name being used
        EMAIL_ADDRESS = the email address in your profile
        TOOLNAME = the name of the Tool that was used
        EMAIL_MSG_WHERE_TO_FORWARD_BACK_TO = the email address that they should forward email tests back to (grabs from pat_user_conf.py)
